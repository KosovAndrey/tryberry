# WB: живая цена карточки вместо архива (📌 КАНОН по источнику цены WB)

Статус: **код готов, НЕ задеплоен** (ветка `fix/wb-live-card-price`, 2026-07-16).
Фиксит баг, найденный 2026-07-15 при отборе товара для промо-скриншотов.

## Симптом

Станция Лайт 2 (nm 376365149, product 8288688): в базе **3 696.02 ₽** от 13.07,
на живой карточке **5 047 ₽**. Публичная `/p/` писала «Дешевле не было за всё
время наблюдения» на цену, которой уже нет.

## Диагноз

Текущая цена бралась **последней точкой архива** `price-history.json` с
basket-CDN (`parseWBHistory`). Архив обновляется с лагом в **дни** (комментарий в
коде обещал «часы»). Cond-GET 304 дополнительно замораживал цену из снимка.

Масштаб по метрике на 2026-07-15: `wb_price_source: basket=100, ucard=3` →
**97% цен WB из архива**. При этом **success rate = 100%**: скрейпер честно
качает файл с CDN, там нет антибота.

> **Успех ≠ правда.** Такой баг метриками не ловился в принципе — только сверкой
> с живой карточкой глазами. Тот же класс, что `ozon-oos-foreign-price-bug`:
> «откуда мы знаем, что эта цена принадлежит этому товару СЕЙЧАС».

## Решение: браузер, НЕ прокси

Прокси отвергнут: xray бережём под TG-egress. Образец — Ozon (браузерный
сайдкар); Я.Маркет тут НЕ образец (он ходит direct без браузера).

Сайдкар с нуля не нужен — расширен **существующий** `wb-search-miner` (уже
прогрет, проходит wbaas, на проде с 2026-07-05):

- **Python** (`wb-search-miner/server.py`): эндпоинт `GET /card?nm=<id>` рядом с
  `/search`. Навигация прогретой дорожкой на страницу товара + перехват `u-card`
  XHR, который фронт делает сам. Транспорт общий с `/search` (`_fetch_intercept`):
  интервалы, стена, re-warm — те же.
- **Go** (`internal/scraper/wildberries.go`): `SetCardBrowser(url)` →
  `fetchFromBrowserCard` — основной источник цены. Живая карточка и архив идут
  **параллельно** (навигация ~1-2с >> basket ~100мс, история почти бесплатна),
  затем живые цена/наличие кладутся поверх архивных имени/картинки/Истории.
- `price-history.json` остаётся **только бэкфиллом истории** — его настоящая роль
  (только WB отдаёт выгружаемую серию).
- Убран захардкоженный `InStock: true`: живая карточка без оффера → честный OOS.

### Точки отката и деградации

| Ситуация | Поведение |
|---|---|
| `WB_CARD_BROWSER_URL` пуст | Цена из архива — ровно как до фикса (рубильник) |
| Сайдкар 502 (нет дорожек) / 403 (стена) | Откат в архив: цена отстаёт, но не пусто |
| `products: []` в ответе | **НЕ** трактуем как OOS (иначе сбой формы разом погасил бы весь WB) → откат в архив |
| Товара нет в basket (трансгран) | Живой карточки достаточно, просто без Истории |

### Метрики

- `wb_price_source{source}` → `browser` (норма) / `basket` (архив, **цена
  отстаёт**) / `ucard`. **Рост доли `basket` = деградация правдивости цен при
  success rate 100%** — следить надо именно здесь.
- `wb_card_fetch_total{outcome}` → `ok|forbidden|no_lanes|empty|error`.

## Открытое: нагрузка на сайдкар (после деплоя)

Замер WB-скрейпов/час **до сих пор не сделан** — он требует прод-доступа.
Грубая оценка ~200/час (3-4/мин) = уровень ozon-miner, должно взлететь на одной
дорожке. Мерить **поштучно по 3 репликам** (`curl <ip>:8090/metrics`)…
— впрочем, после фикса `dns_sd` (ветка `fix/prometheus-scraper-replicas`)
Prometheus видит все реплики, и `sum(rate(...))` уже честный.

Если сайдкар не потянет: пул дорожек (`WB_SEARCH_POOL_SIZE`) либо гибрид
(браузер только активным подпискам).
