# Частота скрейпа по тарифам и маркетплейсам

Задача: определить оптимальную частоту скрейпа WB / Я.Маркет / Ozon / Ali и
разложить по тарифам, отдельно решить про reseller.

## Модель сейчас

Базовый каданс задаёт `Plan.Interval` (источник истины — `domain.Plans`),
эффективный интервал товара/запроса = **MIN по всем подписчикам**:

| план | MaxProduct | MaxSearch | Interval |
|---|---|---|---|
| free | 5 | 0 | 60 мин |
| lite | 20 | 3 | 30 мин |
| trial (3 дня) | 100 | 10 | 15 мин |
| pro | 100 | 10 | 15 мин |
| reseller_start | 5 | 1 | 1 мин |
| reseller_pro | 15 | 3 | 1 мин |
| unlimited | ∞ | ∞ | 1 мин |

Поверх плана — per-маркетплейс правила в `cmd/scheduler/main.go`:

- **Товары** (`productSchedulerTick`): WB/Я.Маркет/Ali — каданс плана как есть.
  Ozon — `× OZON_INTERVAL_MULTIPLIER (2)`, пол `OZON_MIN_INTERVAL_MINUTES (20м)`,
  **reseller-планы по Ozon не скрейпятся вовсе**. Все товарные таски в один топик
  `scrape-tasks` (отдельной reseller-дорожки для товаров НЕТ).
  *(Я.Маркет выведен из антибот-троттла в ветке feat/yandex-raise-rps — теперь он
  как WB; раньше троттлился наравне с Ozon.)*
- **Поиск** (`searchSchedulerTick`): WB/Я.Маркет — каданс плана. Ozon — пол
  `OZON_SEARCH_MIN_INTERVAL_MINUTES (30м)`. Роутинг по дорожкам: эфф.интервал
  ≤ `resellerLaneCutoff (2м)` → `reseller-tasks` (отдельный пул токенов), иначе
  `search-tasks`.

### Эффективный каданс по (план × маркетплейс), товары

| план | WB | Я.Маркет | Ali | Ozon |
|---|---|---|---|---|
| free | 60м | 60м | 60м | 120м |
| lite | 30м | 30м | 30м | 60м |
| pro/trial | 15м | 15м | 15м | 30м |
| reseller | 1м | 1м | 1м | 20м ¹ |
| unlimited | 1м | 1м | 1м | 20м |

¹ Раньше reseller по Ozon-товарам был НЕДОСТУПЕН (исключался). Решение от
2026-06-23: дать доступ на троттл-кадансе (пол 20м), как у остальных Ozon-планов.
Больше дорожек browser-пула Ozon → позже (тогда можно ускорить).

## Что изменилось в вводных (почему задача актуальна)

- **Я.Маркет и Ali теперь дешёвые**: ходят direct с датацентр-IP без прокси
  (probe: YM держит сотни запросов без капчи — docs/YANDEX-WARMED-COOKIES.md;
  Ali — direct+proxy-fallback). Их можно гнать кадансом WB без опасений.
- **WB дешёвый**: basket-CDN + пул токенов.
- **Ozon дорогой и хрупкий**: браузер-сайдкар (FAB), один аккаунт/IP. Частый
  опрос жжёт сессию — троттл оправдан и должен остаться.

Вывод: «дорогой» только Ozon. Для WB/YM/Ali узкое место — не антибот, а
осмысленность (как часто реально меняется цена) и нагрузка на БД/уведомления.

## Принятые решения (2026-06-23)

1. **Reseller × Ozon → доступ на троттл-кадансе (пол 20м)** [сделано]. Убрано
   исключение reseller из Ozon-товаров в `productSchedulerTick`: их 1-мин интервал
   идёт общим Ozon-путём (×2 → пол 20м). Ускорение (10–15м) — после расширения
   browser-пула Ozon (отдельная задача про доп. дорожки).
2. **Базовые интервалы планов — без изменений** (free 60 / lite 30 / pro 15 /
   reseller 1). Разумно привязаны к ценности тарифов; запас у WB/YM/Ali есть, но
   менять без нужды не стали.
3. **Дифференциация по маркетплейсам внутри плана — не вводим.** WB/YM/Ali идут
   единым кадансом плана (вкл. reseller 1м), Ozon медленнее — это уже так.
4. **Товарная reseller-дорожка — НЕ вводим сейчас** (мало перекупов; товары идут
   общим `scrape-tasks`). Вернуться по сигналу нагрузки (см. задачу масштабирования
   notifier/delivery).

Итог по коду: единственная правка — снятие Ozon-исключения для reseller
(плюс ранее в этой ветке — снятие антибот-троттла Я.Маркета). Остальное —
конфигурация/решения, кода не требуют.
