# URL shortener — разбор (нужен ли и как)

Задача из Google Tasks: «сокращать ссылки, чтобы выглядели лучше и короче;
продумать нагрузку — если все ссылки идут через сайт, это быстро?».

## РЕШЕНИЕ (2026-06-30): шортенер НЕ делаем — чистим URL

Выяснилось (на реальном примере страшной ссылки в TG-дайджесте): ~80% длины — это
трекинг-параметры маркетплейса (`cpc`/`do-waremd5`/`ogV` у Я.Маркета; `from`/
`perehod`/`__rr` у Ozon). Шортенер ради этого избыточен (добавляет редирект-хоп +
зависимость от нашего домена). Вместо него — **очистка URL карточки от query+fragment
при показе**:

- хелпер `domain.CleanProductURL(raw)` (internal/domain/url.go) — оставляет
  scheme+host+path, дропает query/fragment; на нераспознаваемом вводе — без изменений;
- применён в точках сборки алертов в `cmd/notifier`: `PriceAlert.ProductURL`
  (одиночный + bundled читает уже почищенный из БД), `SearchAlertItem.URL`, и в
  дайджесте (`main.go`). TG/VK/MAX едят одни структуры → чисто во всех каналах,
  ретроактивно (на уже сохранённых грязных URL — чистится при показе);
- **`SearchURL` (ссылка на выдачу) НЕ трогаем** — там query несёт сам запрос.

Длинный `…/5130704659?do-waremd5=…&cpc=<200симв>&ogV=-12` → `…/card/<slug>/5130704659`.
Тесты: `internal/domain/url_test.go` (4 маркетплейса + edge). Ниже — исходный разбор
вариантов (B/C — на случай, если позже понадобится настоящий шортенер для шеринга/
клик-аналитики).

---

Статус исходного разбора ниже: **не реализовано** (оставлено как справка).

## 1. Где вообще проблема (факты из кода)

Ссылки в сообщениях бота рендерятся по-разному:

| Канал | Ссылка на товар | Ссылка на график |
|---|---|---|
| **Telegram** | `<a href="URL">Название</a>` — **URL скрыт за названием** (ParseMode HTML) | кнопка «📈 График цены» |
| **VK** | **сырой `ProductURL` в тексте** (VK не рендерит HTML) | `📈 График цены: …/p/<public_id>` в тексте |
| **MAX** | **сырой `ProductURL` в тексте** (для разворота превью-карточки) | то же |

Источник текста VK/MAX: `cmd/notifier/delivery.go` → `vkPriceText` / `vkBundledText`
/ `vkSearchText` (общий текст для VK и MAX). Telegram-нотифаер
(`internal/telegram/notifier.go`) уже использует `<a href>`.

**Вывод:** «уродливая длинная ссылка» = это `ProductURL` маркетплейса (WB/Ozon/
Я.Маркет/Ali — реально по 100–200 символов) **только в VK и MAX**. Наш собственный
линк на график (`/p/<public_id>`, 12 hex) и так короткий. В Telegram проблемы нет.

## 2. Ответ на вопрос про нагрузку

> «Если все ссылки короткие, всё идёт через сайт — это быстро?»

Да, быстро, это **не узкое место**:

- Короткая ссылка = `tryberry.ru/<code>` → **302 redirect** на целевой URL.
- Серверная работа на клик: nginx → api → **один индексный lookup** (`code → url`)
  → 302. Это доли миллисекунды + сеть.
- Кликов у трекера цен немного (их жмут изредка при срабатывании). Даже 100k
  кликов/сутки ≈ 1.2 rps в среднем — пренебрежимо. nginx тянет тысячи rps.
- При желании горячие коды кэшируются в памяти/redis (как уже кэшируются страницы
  `/p/` в `cmd/api`) — тогда даже без БД.

Реальные минусы шортенера — **не перформанс**, а:
1. **Зависимость**: наш домен становится точкой отказа для всех ссылок (ляжет сайт —
   ссылки мертвы). Сейчас ссылки ведут напрямую на маркетплейс и живут без нас.
2. **Лишний хоп** редиректа (~50–150 мс сети на клик).
3. **Безопасность open-redirect**: редиректить только на URL **из нашей БД**, никогда
   на произвольный пользовательский ввод. Тогда абуза нет.

## 3. Варианты

### A. Без шортенера — ссылка-кнопкой (минимум усилий)
VK и MAX поддерживают link-кнопки (уже используем для «📈 График цены»). Показать
ссылку на товар **кнопкой** «🛒 Открыть товар», а не сырым URL в тексте.
- **+** ноль инфраструктуры, ноль нагрузки, чистейшее сообщение, без зависимости от нас.
- **−** не закрывает **пачки** (`vkBundledText`: много товаров в одном сообщении —
  по кнопке на товар не сделать, там URL остаются в тексте). Для одиночных алертов — идеально.

### B. Reuse `public_id` → `/l/<public_id>` (рекомендую)
У каждого товара уже есть `public_id` (12 hex, миграция 022) и `URL`. Добавить роут
`/l/<public_id>` → 302 на `product.URL`. **Новой таблицы не нужно.**
- **+** минимум кода (зеркало `/p/` в `cmd/api/webpages.go` + `location ^~ /l/` в nginx),
  переиспользует существующее, работает и для пачек, безопасно (URL из БД).
- **−** код = 12 hex → `tryberry.ru/l/abc123def456` (~33 симв). Короче 150-символьного
  URL WB в разы, но не «тайни». Привязан к товару (для произвольных ссылок не годится).

### C. Отдельная таблица `short_links` (полноценный шортенер)
`short_links(code base62 ~6–7 симв, target_url, type, click_count, created_at)`.
- **+** самые короткие коды, любой URL (вкл. поиск-ссылки/шеринг), счётчик кликов/аналитика.
- **−** миграция + генерация/дедуп кодов + таблица. Оверкилл, если аналитика не нужна.

## 4. Рекомендация

1. **Быстрый эффект:** вариант **B** (`/l/<public_id>`) для VK/MAX — подменять
   `ProductURL` на `tryberry.ru/l/<public_id>` в `vkPriceText`/`vkBundledText`/
   (`vkSearchText` — там ссылка на выдачу, не на товар, можно оставить). Нагрузка —
   не проблема. Переиспользуем кэш и инфру `/p/`.
2. **Опционально для UX одиночных алертов:** добавить вариант **A** (кнопка «Открыть
   товар») — тогда в одиночном пуше вообще нет URL в тексте.
3. **Telegram не трогаем** — там уже `<a href>`.
4. **Вариант C** — только если захотим аналитику кликов или шортить произвольные
   ссылки (шеринг). Пока не нужен.

## 5. Если делаем B — объём работ
- `cmd/api/webpages.go`: роут `/l/<public_id>` → `GetByPublicID` → `302 Location: product.URL`
  (тот же `publicIDRe`, тот же кэш; 404 на неизвестный/битый код).
- `nginx/conf.d/tryberry.conf`: `location ^~ /l/` → проксировать на `api:8081` (как `/p/`).
- `cmd/notifier/delivery.go`: в `vkPriceText`/`vkBundledText` подменять `ProductURL`
  на `<baseURL>/l/<public_id>` (есть `chartBaseURL`/`PublicID` в алерте).
- Метрика кликов (опц.) — счётчик в Prometheus на роуте.
- Тест: редирект 302 + Location; 404 на мусор; безопасность (только из БД).
