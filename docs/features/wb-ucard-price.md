# WB: переход цены карточки на u-card.wb.ru

Статус: **реализовано** (2026-06-22), ветка `feat/wb-ucard-price`.
Закрывает задачу «WB трансграничные/AliExpress товары».

## Зачем

Прежний WB-скрейпер (`internal/scraper/wildberries.go`) брал цену из basket-CDN
`price-history.json`. Три боли (по его же комментариям):
1. перебор basket-шардов (формула `wbBasketNumber` + соседи ±12);
2. цена **отстаёт на часы** (это последняя запись истории, не текущая);
3. **не видит трансграничные** товары («Находки из Китая», напр. `nm=1114323146`) —
   их нет в basket-CDN (перебор баскетов 1-46 пуст), а `card.wb.ru` даёт 404/403.

## Источник цены для трансграничных

Живой наследник мёртвого card.wb.ru:
`https://u-card.wb.ru/cards/v4/list?...&nm={id}` — отдаёт `products[0].sizes[0].
price.product` (копейки, текущая цена), форма = поисковой выдаче (`wbSearchResponse`).

**Но:** u-card **403-ит прямой датацентровый RU-IP** воркера (антибот, веб-сервер
Angie). Работает только через прокси с зарубежным/чистым выходом — у нас это `xray`
(VLESS → Германия, тот же `HTTPS_PROXY`, что у бота; через него `/track`
трансграничного и отдал цену).

## Итоговая схема (вариант B — basket основной, u-card только для трансгран)

Первая попытка была «u-card основным везде» — дала инцидент: `pt_scraper` ходит с
прямого RU-IP → u-card 403 на КАЖДЫЙ товар → всё падало в basket (лишний неудачный
запрос), а один трансграничный товар застрял в ретрай-петле и лагал консьюмер
price-events. Откатано к безопасной схеме:

- `Scrape`: **basket основной** (прямой egress, без антибота, как годами); при
  `ErrProductNotFound` (нет в basket-CDN: удалён/трансгран) → **fallback u-card**.
- u-card-fallback ходит через `s.ucard` — отдельный клиент с прокси
  (`SetUCardProxy`, env `WB_UCARD_PROXY_URL=http://xray:8888` у `pt_scraper`).
  basket при этом остаётся на прямом egress. Нагрузка на xray копеечная — только
  редкие трансграничные.
- `ucardPriceKopecks`: `product` → `total` → `basic`.
- Перманентные ошибки скрейпа (`ErrProductNotFound`/`ErrInvalidURL`) в воркере
  **не ретраятся** (`cmd/scraper`: skip+commit) — иначе один нескрейпящийся товар
  лагает весь консьюмер.
- Метрика `tryberrybot_wb_price_source_total{source=basket|ucard}`: ucard растёт
  только на трансграничных.
- Консистентность: и `/track`, и периодика идут одной логикой (basket→u-card), так
  что baseline товара не расходится между ботом и воркером.

Минус схемы: обычные товары остаются на basket-цене с её лагом (real-time только
для трансграничных). Полный real-time везде потребовал бы гнать ВСЮ периодику через
прокси — отложено (нагрузка/выгорание IP).

## Проверить на VPS

- трансграничный `nm=1114323146` трекается и в `/track`, и в периодике
  (`wb_price_source_total{source="ucard"}` тикает на нём);
- обычные товары — `source="basket"`, лага консьюмера и спайка not_found нет;
- в логах `pt_scraper` для нескрейпящихся — `scrape skipped (permanent)`, без петли.
