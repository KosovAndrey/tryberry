## 2. Правила изменения списка

1. Предоставление доступа к персональным данным любому иному лицу допускается
   только после:
   - внесения этого лица в настоящий Список с указанием роли и минимально
     необходимого объёма доступа;
   - получения от него письменного обязательства о неразглашении персональных
     данных и об обязанности прекратить их обработку в случае прекращения
     отношений с Оператором;
   - ознакомления его с Политикой в отношении обработки персональных данных
     и настоящим Списком под подпись.
2. Доступ предоставляется по принципу минимально необходимых привилегий:
   объём доступа ограничивается данными, без которых выполнение поручаемых
   действий невозможно.
3. При прекращении отношений с лицом доступ отзывается **в тот же день**:
   учётные записи блокируются, пароли и ключи доступа, которые были известны
   этому лицу, подлежат ротации в порядке, описанном в
   `docs/SECRET-ROTATION-RUNBOOK.md`.

## 3. Лица, действующие по поручению Оператора (ч. 3 ст. 6 152-ФЗ)

Организации, которым Оператор поручает обработку персональных данных, к
настоящему Списку не относятся: они не получают доступ к ИСПДн, а обрабатывают
переданные им данные в собственных системах на основании договоров (в том числе
договоров присоединения) и несут ответственность перед Оператором. Их перечень
приведён в разделе 5 документа «Перечень обрабатываемых персональных данных».

## 4. Организационные и технические меры разграничения доступа

- Доступ к серверу — только по SSH с аутентификацией по ключу; парольная
  аутентификация и вход под учётной записью `root` по паролю запрещены.
- Порты СУБД PostgreSQL, Redis и Kafka закрыты для доступа из сети Интернет
  и доступны только внутри изолированной сети контейнеров.
- Прикладные компоненты подключаются к СУБД под учётной записью, не обладающей
  правами суперпользователя.
- Секреты (пароли СУБД, токены ботов, ключи платёжного сервиса и объектного
  хранилища) хранятся вне системы контроля версий, в файле окружения на сервере
  с ограниченными правами доступа; порядок их плановой и внеплановой смены
  описан в `docs/SECRET-ROTATION-RUNBOOK.md`.
- Административные команды бота доступны только идентификаторам, перечисленным
  в конфигурации; действия администратора фиксируются в служебных логах.
