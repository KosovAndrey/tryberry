## TL;DR

Бот (Telegram @TryBerryBot, отслеживание цен/выдачи Wildberries) — рабочий, в проде,
микросервисы в Docker на RU-VM. За последние сессии закрыты три крупные темы из старого
бэклога: **свой egress-прокси (WireGuard+tinyproxy)**, **быстрая дорожка перекупов** и
**полная механика платных тарифов**.

**Главная развилка сейчас:** механика подписок готова целиком (каталог, грейс-периоды,
напоминания, reconciler, мгновенное восстановление при покупке), **но реального приёма
оплаты нет** — тариф выдаётся только вручную админ-командой `/grant`. Чтобы
зарабатывать, следующий шаг — подключить платёжный провайдер (Telegram Stars и/или
ЮKassa) к уже существующей машинерии.

## Что сделано с момента старого хэндофа (всё в `main`)

- **Egress-прокси свой.** Заменили арендованный lteboost на локальные `wg-proxy`
  (WireGuard, туннель wg0) + `tinyproxy` (HTTP CONNECT :8888). api/bot-worker/notifier
  ходят в Telegram через `HTTPS_PROXY=http://wg-proxy:8888`. Подводные камни деплоя —
  в memory `wg-egress-deploy-gotchas`.
- **Латентность приёма команд.** Polling (`WEBHOOK_ENABLED=false`) с узким таймаутом
  long-poll и свежим CONNECT-туннелем на каждый getUpdates (`DisableKeepAlives`).
  Команды доходят за ~2с. Остаточная нестабильность — на плече exit→Telegram (см. ниже).
- **Перекупы (была исходная бизнес-цель «ещё не начато»).** Быстрая дорожка: отдельный
  сервис `cmd/search-worker`, приоритетная очередь (~1-мин скрейп), свой пул токенов,
  реплики. Изоляция SLA от обычного поиска (20 мин).
- **Платные тарифы — полностью построены:**
  - Каталог планов: `free, trial, lite, pro, reseller_start, reseller_pro, unlimited`.
  - Строгий per-plan интервал проверки (миграция 010) — у дорогих планов чаще.
  - Грейс-период после истечения для поиск- и товарных подписок (reconciler).
  - Напоминания об истечении, мгновенное восстановление трекинга при покупке.
  - Тесты reconciler (`internal/domain/plan_test.go`).
  - Миграции 004–010 (`plans`, `plan_grace*`, `plan_reminded`, `search_tiers`,
    `per_plan_intervals`).
  - Выдача плана: **только** `/grant <telegram_id> <план> [дней]` (admin.go) — оплаты нет.

- **Фикс ложных уведомлений поиск-подписок (2026-06-11, задеплоено, f386f8c).**
  Новый товар в выдаче показывал зачёркнутую цену WB (`price.basic`) как «было X ₽» —
  выглядело как ложное «подешевело» (особенно `below_target`, срабатывающий сразу).
  Теперь в `SearchHitEvent` идёт `prev_price_kopecks` — опорная цена, от которой движок
  реально считал снижение (`last_notified` или baseline `first_seen_price`); для впервые
  увиденного товара она равна текущей и «было» не печатается. Сортировка топа в notifier —
  тоже по реальному снижению. Зачёркнутая цена в уведомлениях больше не участвует нигде.
  Хелпер `searchsub.RefKopecks` + тест. Пересобраны `search-worker`, `reseller-worker`,
  `notifier`.

Сервисы сейчас: `api` (ingestor), `bot-worker`, `notifier`, `scheduler`, `scraper`,
`search-worker`.

## Открытые задачи / что можем сделать дальше

### A. Монетизация — подключить оплату (рекомендация №1)
Вся подписочная механика уже есть, не хватает только приёма денег.
- **Telegram Stars (XTR)** — самый быстрый путь: `sendInvoice` (currency `XTR`),
  обработчик `PreCheckoutQuery` → `SuccessfulPayment` → дёргаем существующий `SetPlan`.
  Не требует юрлица/эквайринга, работает прямо в боте.
- **ЮKassa** — для рублёвых платежей и вывода денег; требует самозанятости/оферты,
  Telegram Payments provider token. Можно вторым шагом.
- По сути нужно: кнопки «Купить план» в боте → invoice → на `SuccessfulPayment`
  вызвать уже готовый `userRepo.SetPlan` с нужным сроком. Машинерия восстановления
  трекинга при покупке уже реализована.

### B. Стабильность Telegram-плеча → VLESS (РАЗВЁРНУТО 2026-06-11)
- Симптом был: бот иногда отвечал 25с — флап на удерживаемых long-poll через WireGuard
  (UDP, РКН троттлит по DPI).
- Решение в проде: основной egress на **VLESS+Reality** (TCP под HTTPS), 6 узлов
  подписки un1.pro (`vless-ger1..6`) + WG как авто-fallback. Контейнер `xray`
  (inbound :8888, observatory+balancer leastPing). Подтверждено логами
  `[in -> vless-ger1]`, exit-IP немецкий.
- Осталось: понаблюдать, что флап на 25с ушёл. Опц.: строгий приоритет/расширение
  пула узлов через тот же balancer.

### C. Безопасность (техдолг, светилось в чате)
- Сменить root-пароль VPS и пароль прокси, перейти на SSH-ключи, ограничить порт прокси.
- Отозвать старый bot-токен у @BotFather.

### D. Инфраструктура
- Ротация docker-логов (`logging: max-size/max-file` в compose).
- Cron на `docker builder prune -af` (диск RU-VM был на 94%).
- Переезд на 8 CPU / 16 ГБ / 180 ГБ NVMe снимет тесноту.
- При росте нагрузки на приём команд — Шаг 2b: убрать `container_name` у bot-worker →
  `up -d --scale bot-worker=N` (безопасно: FSM в Redis, ключ = user ID).

### E. Новые маркетплейсы (после монетизации)
- Ozon / Я.Маркет — пока заглушки (`internal/scraper/ozon.go`, `yandex_market.go`).
  Гипотеза: внутренний JSON-API карточки + обязательные cookie (аналог токена WB).
  Проверить нужен ли прокси и юнит-экономику. Гео-чувствительны → RU-сервер/прокси.
