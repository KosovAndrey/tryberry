# product-match — прототип сопоставления товара между площадками

Вторая ось «честной цены»: не «дешевле, чем было», а «дешевле, чем этот же товар
у других». Замысел, границы и отвергнутые альтернативы —
[`docs/PRODUCT-MATCH-JVM.md`](../docs/PRODUCT-MATCH-JVM.md).

**Это прототип для ЗАМЕРА, а не сервис.** Он существует, чтобы получить число,
с которым сравнивается триграммный baseline (`scripts/trgm-baseline.py`). Условие
отказа записано заранее: не будет заметного отрыва — сервис не пишем.

## Запуск

```bash
export JAVA_HOME=~/.local/tools/jdk-21.0.12+8
export PATH="$JAVA_HOME/bin:$HOME/.local/tools/apache-maven-3.9.9/bin:$PATH"

mvn -q test        # доменная нормализация
mvn -q compile
mvn -q exec:java -Dexec.mainClass=ru.tryberry.productmatch.Main \
  -Dexec.args="--items ../testdata/product-match/items-smartphones.tsv \
               --pairs ../testdata/product-match/gold-smartphones.tsv \
               --out /tmp/lucene-scored.tsv"
```

## Что считает

**Оценку на каждую пару** размеченного набора — чтобы сравнение с триграммами шло
на одном и том же наборе и теми же метриками.

**recall@K** — долю настоящих пар, попавших в топ-K кандидатов. Решающее число
для вопроса «нужны ли эмбеддинги»: высок — векторам негде добавить ценность,
потому что слой решения всё равно перебирает всех K.

## Что стоит знать, прежде чем править

**Два этапа с противоположными метриками.** Индекс здесь — только ОТБОР, он
оптимизирует recall, и точность на нём не важна. Точность даёт отдельный слой
решения с правом отказа. Смешать их — значит потерять и то, и другое.

**Индекс не решает главный тип ошибки.** На синтетике трудный негатив (тот же
телефон, другой объём памяти) получает оценку почти вровень с настоящей парой.
Поэтому несовпадение объёма обязано быть ОТКАЗОМ, а не минусом к скору.

**Доменная нормализация дублируется с `scripts/make-pairs.py`.** Бренды, объёмы,
модельные коды разбираются по одинаковым правилам в двух местах — иначе baseline
и индекс сравниваются на разных признаках. Правишь одно — правь второе.

**`\b` в Java по умолчанию ASCII.** Граница слова после кириллического «гб» не
срабатывает без `UNICODE_CHARACTER_CLASS`, и объём памяти молча перестаёт
распознаваться. Ровно этот баг поймал `NormalizationTest`.
